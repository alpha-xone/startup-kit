# web-design-guidelines — Preflight 报告渲染规范

> **本文件不再定义配色与字体。** 报告的视觉层由 `impeccable` skill 拥有，图表由 `diagram-design` skill 拥有。
> 本文件只定义三件事：**渲染委派**、**状态语义**、**报告必须承载的信息结构**。
>
> 旧版此处的 slate/蓝硬编码配色（`#1e293b` / `#3b82f6` / `#f8fafc` / `-apple-system` 字族）已**废弃**，不要再用。

---

## 一、渲染委派（硬性流程）

生成任何 Preflight HTML 报告时，按这个顺序做，不要跳步。

### 1. 视觉层 → 调用 `impeccable` skill

- 单项目报告属于 impeccable 的 **Read 模式**（读者要读懂一份诊断）；批量对比仪表盘偏 **Operate**。按对应模式走。
- 先跑一次 `node <skill-base-dir>/scripts/context.mjs --target <报告路径>`，按它的 directive 加载对应 playbook；进入实际编辑前加载 `reference/craft-floor.md`。
- 在一个没有 PRODUCT.md 的项目里，`context.mjs` 会报 `BUILD_INIT_REQUIRED`。那套流程是给**你会长期迭代的产品界面**准备的。报告是一次性交付物，**不要**为了它先跑 `init` 做一轮产品访谈，也不要因为项目缺 DESIGN.md 就停下来问用户——直接按 Read 模式产出，交付后一句话提示 `init` 是可选的后续。**例外**：目标项目已经有 PRODUCT.md / DESIGN.md 时照它执行，不要另起一套。
- 沿用 impeccable 的质量底线。对本报告影响最大的几条（旧版设计正好全部踩中，一并纠正）：
  - **禁止**在标题上方加 eyebrow / kicker 小标签。
  - **禁止**用 `border-left` / `border-right` 彩色竖条做装饰（旧版 `.conclusion` 的 4px 竖条、`.action-item` 的 3px 竖条都是错的）。
  - **禁止**拿 emoji / Unicode 符号当图标系统（旧版用 ✅ ⚠️ 📈 表状态）。状态图标用统一描边的一套自绘 SVG — 见 `diagram-design` 的 `references/primitive-icons.md`。
  - **禁止**用同尺寸的「图标 + 标题 + 正文」卡片铺满页面当骨架。维度分数卡是**数据展示**（维度名 + 分数 + 趋势），不是卡片墙。
  - 不要渐变文字、玻璃模糊、无偏移的彩色光晕、硬投影这些装饰。

### 2. 图表层 → 调用 `diagram-design` skill

- 报告里**每一张图**都用 diagram-design 画，产出自包含 HTML + 内联 SVG。**不要**手写雷达图，**不要**引 Chart.js 或任何图表库，**不要**用 canvas。
- **默认 light**：用 `assets/template.html`（minimal light）；报告是卡片式长文时用 `assets/template-full.html`。
  除非用户明确要深色，**不要**用 `template-dark.html` 或任何 `example-*-dark.html`。
- 首次在某个项目里画图会触发它的 style-guide gate。报告场景**直接选 (e) 沿用默认**（纸白 paper + ink + 原子橘 accent），不要为此打断用户；只有当报告目标项目已自带 DESIGN.md / 品牌 token 时才走对应分支。
- **必须先加载所选图型的 `references/type-*.md`** 再画，并按其中的复杂度预算裁剪（节点 / 系列 / 轴数上限）。
- 交付前跑自检：`python scripts/self_check.py <file>`；仓库检出里另有几何校验脚本时一并跑。

#### 图表 → 图型映射（报告常用）

| 报告里要表达 | 用哪个图型 | 备注 |
|---|---|---|
| 单项目维度得分 | **Bar chart**（`type-bar.md`） | 12 维 → 首选横向条形图，按分排序。条数上限 8，超了分两张或先聚合 |
| 6 大类聚合得分 | **Radar**（`type-radar.md`） | ⚠️ 雷达轴上限 **5**。12 维**不能**直接画雷达 — 先聚合成 ≤5 轴，否则回到条形图 |
| 多项目对比 | 分组 **Bar**，或 **Quadrant**（`type-quadrant.md`，两轴 = 综合分 × 风险） | 项目数 ≤8（bar）/ ≤12（quadrant） |
| 多轮 loop 复查的分数变化 | **Line**（`type-line.md`）或 **Slopegraph** | 系列 ≤5 |
| 闸门流水线 G0→G4 | **Flowchart**（`type-flowchart.md`） | 节点 ≤9 |
| 行业失败原因分布 | **Bar**，或 **Treemap**（`type-treemap.md`，≤8 格） | |
| 验证/推进时间线 | **Timeline**（`type-timeline.md`）或 **Gantt**（`type-gantt.md`） | |

- **先判断该不该画**：三行表格能说清的就别画。
- 一次报告里图表克制：**1–2 张主图**，其余用表格。
- 止损线检查**不要**画图，用「已触发 / 未触发」两列表格更清楚。

#### 把 diagram-design 的产出嵌进报告

- 取它产出的**那个 `<svg>` 节点**（连带其中的 `<title>` / `<desc>`）内联进报告的 HTML。**不要** iframe，**不要** `<img src>` 外链，**不要**截图。
- 一个报告里会有多张图，`<title>` / `<desc>` 的 id 必须逐图改名（`<slug>-title` / `<slug>-desc`），否则 id 撞车。
- 字体：diagram-design 用一份 Google Fonts `<link>`。报告允许保留**这一条**外链（带 `preconnect` + `display=swap`），其余一律不得外链。需要完全离线时删掉该 link，退回系统字体族并在交付说明里注明。
- 报告整体仍是**单文件自包含**（`<style>` 内联、无框架、无构建）。状态切换之类的小交互可以用内联 `<script>`；图表本身不要靠 JS 绘制。

### 3. 本文件 → 只管内容与语义

---

## 二、模式：默认 light

- 报告默认**浅色**：纸白 / 白底、深墨字。深色只在用户明确要求时给，且同一次交付内不混用浅深。
- 打印 / 导出 PDF 必须可读：浅底 + 保留状态色。
- 正文与表格文字对比度 ≥ 4.5:1，大字号 ≥ 3:1。

---

## 三、状态语义（本 skill 唯一固定的颜色）

状态色是**内容语义**（GO/迭代/KILL 就是结论本身），不是视觉风格，所以它固定在本文件里，由 impeccable 与 diagram-design 当作语义色取用：

| 状态 | 色值 | 用在 |
|---|---|---|
| 🟢 GO | `#16A34A` | 综合分 ≥3.5、GO 标签、通过项 |
| 🟡 迭代 | `#D97706` | 综合分 2.5–3.5、迭代标签 |
| 🔴 KILL | `#DC2626` | 综合分 <2.5、KILL 标签、已触发的止损线 |
| ⚪ 未评分 / 中性 | `#6B7280` | 缺数据项、对标基线 |

规则：

- 除此之外**一切**颜色（背景、卡片、边框、强调、图表分类色）由 impeccable / diagram-design 的主题决定。**不要**在本报告里另立 slate/蓝配色。
- **不得只靠颜色传达状态**：同时给文字（GO / 迭代 / KILL）或形状（实心 / 空心 / 斜线）做第二重编码，色盲可读。
- 同一个报告里同一状态只能用同一个色。
- **多系列图的分类色**不要沿用旧版那串蓝橙绿紫粉固定序列 —— 由 diagram-design 的 style-guide 决定；只有类别**恰好就是** GO / 迭代 / KILL 时才用上表的三个状态色。

## 四、报告必须承载的区块

这是**内容契约**，不是版式。版式由 impeccable 定；下面每一项都必须能在报告里被找到。

### 单项目报告

1. **结论区** — 项目名 · 轮次 · 日期 · 决策标签（GO / 迭代 / KILL）+ 一句话结论。
2. **得分区** — 各维度得分（数值 + 趋势 ↑ ↓ →）。缺数据的维度明确标「未评分」，**不要**填 0 冒充。
3. **图表区** — 1 张主图（维度得分）。多轮复查时补 1 张分数变化图。
4. **维度详情** — 每个维度的判断 + 证据（案例名 / 金额 / 统计量）。可折叠，但默认能看到结论行。
5. **深度追问** — 命中触发条件的深度问题与结论（见 `conditional-diagnostics.md`）；未触发就不出现。
6. **行业与墓园对照** — 该项目的行业失败画像 + 可类比的大厂 / 墓园案例。
7. **止损线检查** — 每条止损线的条件 + 是否触发。
8. **下一步行动 + 待补证据** — 具体动作、时限、还缺什么证据。

### 批量对比仪表盘

1. 项目卡片：名称 · 综合分 · 决策标签 · 三个关键维度分。
2. 对比图：分组条形图或四象限。
3. 推荐行动：推进 / 调整 / 斩杀，逐项点名。

### 响应式

- 窄屏单列、宽屏两列或并排。表格在窄屏允许横向滚动，不要压到不可读。
- 最大宽度由 impeccable 定，**不要**在这个文件里钉死 px。

---

## 五、降级路径（仅当两个 skill 都不可用时）

`scripts/generate-dashboard.py` 是**保底后备**：它不依赖任何 skill，直接吐出一份结构完整的单文件 HTML。只在两个 skill 都装不上、或需要可复现的确定性输出（批量跑分、脚本化出报表）时才用它。它的样式是旧的、**不遵循本文件** —— 用它之前先告诉用户这一点。

---

## 六、交付前检查（逐条过）

- [ ] 报告是**浅色**的，单文件自包含（除 diagram-design 那一条 Google Fonts link）。
- [ ] 视觉层确实走了 impeccable（Read / Operate 模式 + `craft-floor.md`），不是自己拍脑袋的配色。
- [ ] 每张图都是 diagram-design 画的，已加载对应 `type-*.md`、在复杂度预算内、过了 `self_check.py`。
- [ ] 雷达轴 ≤5；12 维得分没有被硬塞进雷达。
- [ ] 状态色只有 GO / 迭代 / KILL / 中性四种，且状态有非颜色的第二重编码。
- [ ] 无 eyebrow、无彩色 `border-left` 竖条、无 emoji 当图标、无渐变文字 / 玻璃模糊。
- [ ] 第四节单项目 1–8 项（或批量版 1–3 项）全部能在报告里找到。
- [ ] 打印预览可读，窄屏不溢出。
